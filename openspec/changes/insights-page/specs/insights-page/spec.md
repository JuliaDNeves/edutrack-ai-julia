# insights-page Specification

## Purpose

Define the interface structure, sidebar and mobile navigation integration, and on-demand visualization of personalized academic insights and diagnostics within the dedicated EduTrack `pages/insights.html` page.

## ADDED Requirements

### Requirement: Dedicated Insights Page Structure and Navigation
The system SHALL provide a dedicated `pages/insights.html` page accessible from the sidebar and mobile bottom navigation across all application views. The page SHALL feature EduTrack's responsive shell, top header with student greeting and motivation tip, a left navigation menu with the "Insights" item highlighted as active, and a central container dedicated to academic insights.

#### Scenario: User navigates to Insights page from sidebar
- **WHEN** the user clicks the "Insights" menu item in the navigation sidebar
- **THEN** the system SHALL navigate to `pages/insights.html` and visually highlight the "Insights" item (`#nav-insights`) as the active navigation state

#### Scenario: Responsive navigation on mobile devices
- **WHEN** the user accesses `pages/insights.html` on small screens or mobile viewports
- **THEN** the system SHALL render the navigation bar at the bottom with icons, highlighting the Insights icon as active

### Requirement: On-Demand Insights Execution on Dedicated Page
The system SHALL display an initial invitation state on `pages/insights.html` with a prominent "Gerar insights" button. The system SHALL initiate academic analysis strictly upon user click and SHALL NOT execute requests automatically on page load.

#### Scenario: Initial InsightsPage load without automatic requests
- **WHEN** an authenticated user opens or reloads `pages/insights.html`
- **THEN** the system SHALL display the initial invitation banner and the "Gerar insights" button without making automated calls to backend analysis endpoints or AI services

#### Scenario: User triggers insights generation on demand
- **WHEN** the user clicks the "Gerar insights" button
- **THEN** the system SHALL initiate an asynchronous request to the insights endpoint (`/api/insights`), transition the action button to a loading state with spinner, and prepare the content container for results

### Requirement: Structured Insights Results Presentation Cards
The system SHALL display the academic analysis results on `pages/insights.html` structured into four organized cards:
1. "Resumo Geral": contextualized qualitative overview of student progress.
2. "Diagnósticos por Disciplina": cards per subject with completion progress, task distribution, and visual temporal variance badges ("dentro do esperado", "subestimado", "superestimado" or "sem tempo registrado").
3. "Recomendações Práticas": prioritized actionable study advice list.
4. "Pontos Fortes": highlighted achievements and strengths.

#### Scenario: Successful insights display with structured cards
- **WHEN** the insights endpoint returns HTTP 200 with the analysis payload
- **THEN** the system SHALL render the four structured cards ("Resumo Geral", "Diagnósticos por Disciplina", "Recomendações Práticas", "Pontos Fortes") populated with data from the response

#### Scenario: Per-subject diagnostic with temporal variance tag
- **WHEN** displaying the diagnostic card for a subject that has evaluated study time
- **THEN** the system SHALL render the completion percentage, task counts, and a status tag indicating whether study time was within expectations, underestimated, or overestimated

#### Scenario: Per-subject diagnostic without recorded study time
- **WHEN** displaying a subject with no completed tasks with recorded spent time
- **THEN** the system SHALL render an informative badge indicating that study time was not registered, without fabricating hours or percentage variance

### Requirement: Visual Loading and Error States
The system SHALL provide distinct visual feedback during request processing and error handling on `pages/insights.html`.

#### Scenario: Active analysis loading feedback
- **WHEN** an insights request is in progress
- **THEN** the system SHALL disable the "Gerar insights" button, display an animated spinner with loading label ("Gerando insights com IA..."), and preserve layout stability

#### Scenario: Request failure error handling
- **WHEN** an insights request fails due to network or server unavailability
- **THEN** the system SHALL re-enable the action button and display a clear error card with a retry option without breaking page layout

### Requirement: Engine Origin and Fallback Badge Indicator
The system SHALL render a visual badge in the insights header on `pages/insights.html` indicating whether the presented recommendations were generated by the AI language model (Google Gemini) or by the deterministic contingency engine (fallback).

#### Scenario: Insights generated by AI model
- **WHEN** the API response contains `ai_engine.status === "success"`
- **THEN** the system SHALL display a badge with an AI icon and label indicating generation via artificial intelligence ("Gerado com IA")

#### Scenario: Insights generated via deterministic fallback
- **WHEN** the API response contains `ai_engine.status === "fallback_used"`
- **THEN** the system SHALL display an informative contingency badge indicating heuristic generation ("Regras Heurísticas / Modo Offline") with an explanatory tooltip
